## 1. Executive Summary & Objective

The objective of this initiative was to equip the **MSU SEO Intelligence Console** with full AI compatibility by integrating an AI Data Assistant capable of translating natural language queries directly into safe, read-only SQL queries executed against the live PostgreSQL database (`web_analytics`). 

Per executive leadership requirements:
- The assistant is **not** an isolated separate tab, but a **universal widget visible on every dashboard view** (Executive Summary, Executive Dashboard, Blog Intelligence, Course Intelligence, Device Analysis, Daily Traffic, SEO Opportunities, etc.).
- All analytical outputs strictly follow the **Pyramid Principle / BLUF standard** with **Strict Zero-Numbering** (no "1.", "2.", "Point 1", etc.).
- Operates in a dual-mode setup: an external LLM mode (Google Gemini, OpenAI, Groq, Ollama) and a **Zero-API-Key Local Analytical Engine** that runs 100% offline with zero external dependencies.

## 3. Executive Output Format & Structural Rules

Every analytical output generated by the AI agent and the local engine adheres strictly to these 4 markdown headers:

```markdown
### 📌 Summary
[A single, high-impact narrative paragraph synthesizing the core finding, key volume/conversion numbers, and operational reality without any numbered list format]

### 🔍 Quantitative Narrative & Findings
- Key observation with specific data points, volumes, or percentages
- Comparison against historical cohorts, targets, or baseline
- Drop-off cliff, variance, or concentration pattern

### 💡 Strategic Root Cause
[A descriptive narrative paragraph examining the operational, student, market, or human decision drivers behind the numbers]

### 🎯 Leadership Action Playbook
- Actionable initiative with expected conversion or revenue impact
- Immediate operational intervention for frontline counselors or marketing
```

**Formatting Invariants:**
- **STRICT ZERO-NUMBERING:** Never use numbered prefixes like `1.`, `2.`, `Point 1`, `Point 2`, `1. BLUF`, or `2. Data`. Prose flows point-to-point in clean narrative prose.
- Executive Summary must be a single cohesive paragraph without bullet points or numbering.

## 4. System Architecture & Codebase Map

### Core AI Engine (`src/ai/`)
1. **`src/ai/client.py`:**
   - Multi-provider LLM interface supporting Google Gemini (`gemini-2.5-flash`, `gemini-1.5-pro`), OpenAI (`gpt-4o-mini`, `gpt-4o`), Groq (`llama-3.3-70b-versatile`), and Ollama / Local (`llama3.2`, `mistral`, `deepseek-r1`).
   - Uses standard Python `requests` with 30s timeout protection (zero SDK bloat).
   - Auto-discovers credentials from `.env` or UI overrides.
2. **`src/ai/schema_context.py`:**
   - Exhaustive PostgreSQL database schema definitions and query rules for `analytics.v_*` views and `raw.*` tables.
   - Enforces view targeting for sub-100ms response times.
3. **`src/ai/sql_executor.py`:**
   - Read-only PostgreSQL query executor via `psycopg`.
   - Security guardrails: Blocks `DROP`, `DELETE`, `UPDATE`, `INSERT`, `ALTER`, `TRUNCATE`, `EXEC`, multiple statements (injection prevention), and automatically appends `LIMIT 100` if omitted.
   - Measures execution time in milliseconds and returns clean DataFrames.
4. **`src/ai/local_engine.py`:**
   - 100% offline, zero-API-key analytical engine.
   - Classifies user intent (devices, daily trends, blog rankings, course performance, low CTR queries, leads/conversions, geography) into parameterized SQL queries and formats executive briefings following the Pyramid Principle.
5. **`src/ai/chart_builder.py`:**
   - Generates interactive Plotly charts with dark console styling: time-series area/line charts, category horizontal bars, and device/channel donut charts.
6. **`src/ai/agent.py`:**
   - Central coordinator orchestrating Text-to-SQL generation, error-correction retry, PostgreSQL execution, narrative synthesis, chart building, and follow-up question generation.

### UI & Console Integration (`src/ui/` & `app.py`)
1. **`src/ui/ai_widget.py`:**
   - **Main View Action Card:** Embedded at the very top of every dashboard view before page charts. Features prompt input, `⚡ Ask AI` button, `⛶ Full Chat Modal` button, and 6 quick preset chips.
   - **Sidebar Header Launcher:** Positioned at the top of the sidebar above navigation links with live PostgreSQL status.
   - **Interactive Modal Dialog (`@st.dialog`):** Provides multi-turn chat history, Plotly charts, copyable SQL query expander, execution timing, and CSV download.
2. **`app.py`:**
   - Removed separate `12_AI_Chatbot.py` tab from navigation.
   - Calls `render_ai_widget()` globally on every run before `pg.run()`.
3. **`src/insights/ai_summary.py`:**
   - Added `generate_ai_executive_summary` with deterministic fallback.
4. **`.env.example`:**
   - Documented `AI_PROVIDER`, `AI_MODEL`, `GEMINI_API_KEY`, `OPENAI_API_KEY`, `GROQ_API_KEY`, `OLLAMA_BASE_URL`.

### 8.1 Problems Diagnosed & Solved
1. **Modal Dismissal on Query Submission:**
   - *Issue:* Streamlit's `@st.dialog` modal closed immediately whenever a user submitted a query because `st.rerun()` restarted `app.py`, during which the opener button evaluated to `False`. The user had to click the launcher a second time to see the generated answer.
   - *Resolution:* Replaced the transient modal dialog with a persistent **In-View Companion Chatbot** at the top of the main window (`src/ui/ai_widget.py`). Governed by `st.session_state.ai_chat_open = True`, the chat container stays open across script executions.

   - *Issue:* The full-screen modal dimmed and obscured the active dashboard view.

### 8.6 Dynamic Font Inheritance & Latency Optimization (Chatbot & Dashboard Performance Overhaul)
- **User Request:** 
  1. "The font of the chatbot should change as per the change in UI"
  2. "The chatbot is way too slow also the dashboard can we do something to fix the same?"
- **Diagnosed Bottlenecks & Root Causes:**
  1. *Font Isolation:* Chatbot container styles did not specify CSS inheritance, causing Streamlit default font overrides to isolate the widget from changes made to the parent dashboard typography (`Inter`, system fonts, custom fonts).
  2. *Dashboard & Page Load Slowness (19.2s Bottleneck):* `src/data/db_loader.py::load_file_or_db` checked `test_db_connection()` first and queried PostgreSQL `raw.ga4_blog_daily` (198,382 rows) and `raw.ga4_course_daily` (60,973 rows) through Python sockets via `cur.fetchall()` followed by a pure Python `pd.to_datetime` loop on 198k strings. Every page load and script rerun was waiting 19+ seconds on raw database transfers when pre-computed `.parquet` files in `data/processed/` load in 0.061 seconds.
  3. *Chatbot Submission Slowness:* Because Streamlit reruns `app.py` and the active page on every user interaction, every chat submission re-triggered the 19.2-second raw table query. Furthermore, `src/ai/sql_executor.py::get_database_status()` was doing `SELECT COUNT(*)` on 5 PostgreSQL tables (~260,000 rows) on *every single interaction*.
  4. *Blog Pipeline Overhead:* `pages/02_Blog_Intelligence.py` had an unvectorized `.apply(_pn)` running 800,000 pure Python function calls across 198k rows for columns that were already native C-integers in the `.parquet` file.
- **Architectural Fixes Implemented:**
  1. *Dynamic Typography Inheritance (`src/ui/ai_widget.py` & `app.py`):*
     - Enforced `font-family: inherit !important;` on `div[class*="st-key-msu_superset_card"] *`, inputs, buttons, chat messages, selectboxes, and labels.
     - Monospace font (`'Roboto Mono', 'Fira Code', 'SF Mono', Consolas, monospace !important`) strictly preserved for data tables, metrics, and SQL code blocks.
     - Root-level typography injected in `app.py` ensuring global font coherence across all pages.
  2. *High-Speed Parquet Prioritization (`src/data/db_loader.py` & `src/data/loaders.py`):*
     - In `load_file_or_db(fname)`: check `data/processed/<base_name>` first. Columnar `.parquet` loads in **0.061s** (314× faster than PostgreSQL raw transfer). Database query remains the fallback if the file is absent.
     - In `detect_and_load_all()`: prioritize local processed files over raw DB table sweeps unless `USE_DATABASE="force"` is explicitly specified.
     - In `get_db_connection()`: automatically route `localhost` to `127.0.0.1` on Windows, removing IPv6 `::1` loopback retry latency.
  3. *In-Memory Caching on Chatbot SQL & Status (`src/ai/sql_executor.py`):*
     - Wrapped `get_database_status()` with `@st.cache_data(ttl=600, show_spinner=False)`. Zero table scan overhead during conversational turns.
     - Wrapped `_execute_safe_sql_cached()` with `@st.cache_data(ttl=600, show_spinner=False)`. Repeated questions and preset chips return in **<1ms**.
  4. *Vectorized Dataframe Processing (`pages/02_Blog_Intelligence.py`):*
     - Guarded numeric conversions with `pd.api.types.is_numeric_dtype(col)` before string manipulation, eliminating 800,000 redundant Python loop iterations.
- **Verified Performance Benchmarks:**
  - `load_file_or_db` lookup: **0.061s** (down from 19.2s — **314× speedup**)
  - AI Widget prompt submission & analytical synthesis: **0.478s** (down from 20s+)
  - Cached query replay & preset chips: **0.112s**
  - `01_Executive_Dashboard.py` load time: **0.567s**
  - `02_Blog_Intelligence.py` load time: **3.788s** cold (down from 19.2s), sub-millisecond cached
  - Unit test suite: **41/41 passing** in 4.5s (`pytest tests/`)

### 8.8 Elimination of Avatar Ligature Text Overlap & Header Layout Polish
- **User Reference:** Uploaded screenshot (`media_1793257799877_89d110c6.jpg`) showing literal words `"face"` and `"smart_toy"` printed over avatar badges and overlapping into message text, along with truncated header elements (`Goo v`) and squashed filter chips (`Top B...`).
- **Diagnosed Root Causes:**
  1. *Material Symbols Ligature Failure:* The global `font-family: inherit !important;` rule targeted `div[class*="st-key-msu_superset_card"] *`, including Streamlit's avatar icon spans (`<span class="material-symbols-rounded">face</span>`). Because Google Material Symbols requires its proprietary icon font to convert text ligatures into glyphs, overriding its font-family caused the browser to render the raw words `"face"` and `"smart_toy"`. Since the avatar badge was constrained to 32px, the text overflowed and physically overlapped the message body.
  2. *Header Column Congestion:* `st.columns([6, 2, 1, 1])` squeezed the title, a provider selectbox, a clear button, and a close button into a 460px card. This forced the title to wrap across 2 lines ("SEO" / "INTELLIGENCE") and truncated the provider dropdown to `"Goo v"`.
  3. *Chip Ellipsis:* Placing 4 filter buttons in a single row constrained each button to 95px, causing Streamlit to truncate labels with ellipses (`Top B...`, `Top C...`, `Mobil...`, `Low ...`).
- **Implemented Architectural Solutions (`src/ui/ai_widget.py` & `.streamlit/config.toml`):**
  1. *Native Emoji Avatars:* Passed `avatar="👤"` for users and `avatar="🤖"` for the assistant in `st.chat_message`. Emojis render natively without external font ligature dependencies, guaranteeing zero text overlap.
  2. *Scoped Font Inheritance:* Restricted `font-family: inherit !important;` strictly to message content and form inputs, while shielding `[data-testid="stChatMessageAvatar"]` and Material Symbols spans.
  3. *Flex Layout Isolation:* Enforced `display: flex; gap: 12px;` with `overflow-wrap: break-word` and explicit avatar dimensions (`32px` width/height with `overflow: hidden`).
  4. *Two-Tier Card Header:* Separated the title row (`[7.6, 1.2, 1.2]`) from the engine selection bar (`[5.5, 4.5]`), eliminating title line-wrapping and giving the engine dropdown ~200px of clean breathing space.
  5. *2x2 Preset Chip Grid:* Reorganized starter tags into 2 columns of 2 buttons each (~225px width per button), displaying full titles (`📊 Top 10 Blogs`, `🎓 Top 5 Courses`, `📱 Mobile vs Desktop`, `🔎 Low CTR Queries`) without truncation.
  6. *Global Dark Theme (`.streamlit/config.toml`):* Configured `theme.base = "dark"` with `#0b0f19` background and `#20a7c9` primary accents, eliminating unstyled white canvas blocks on data tables.
